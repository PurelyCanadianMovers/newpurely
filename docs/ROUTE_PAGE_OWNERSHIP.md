## Supporting hub ownership

`site-copy/calgary-long-distance-movers/index.html` is the authoritative checked-in Calgary hub document. `generate-spa-routes.mjs` must preserve that document. The Calgary-specific writers `rebuild-calgary-ottawa-routes.mjs` and `update-calgary-hub-routes.mjs` share `tools/calgary-hub-routes.mjs` and may replace only the marked `<!-- pcm-calgary-route-list -->` section with the canonical route-list block. Neither script owns or regenerates the rest of the hub.

`site-copy/toronto-long-distance-movers/index.html` is the authoritative checked-in Toronto hub document. `generate-spa-routes.mjs` must preserve that document. `tools/toronto-hub-routes.mjs` owns the canonical Toronto-origin route inventory and marked `<!-- pcm-toronto-route-list -->` block; `rebuild-ottawa-toronto-routes.mjs` may update only that block. No route writer owns or regenerates the rest of the Toronto hub.

`site-copy/ottawa-long-distance-movers/index.html` is the authoritative checked-in Ottawa hub document. `generate-spa-routes.mjs` must preserve that document. `tools/ottawa-hub-routes.mjs` owns the canonical Ottawa-origin route inventory and marked `<!-- pcm-ottawa-route-list -->` block; `rebuild-calgary-ottawa-routes.mjs`, `rebuild-ottawa-toronto-routes.mjs`, and `rebuild-victoria-ottawa-route.mjs` may update only that block. No route writer owns or regenerates the rest of the Ottawa hub.

`site-copy/victoria-long-distance-movers/index.html` is the authoritative checked-in Victoria hub document. `generate-spa-routes.mjs` must preserve that document. `tools/victoria-hub-routes.mjs` owns the canonical Victoria-origin route inventory and marked `<!-- pcm-victoria-route-list -->` block; `rebuild-victoria-ottawa-route.mjs` may update only that block. No route writer owns or regenerates the rest of the Victoria hub.

## Deterministic aggregate policy

`npm run routes` delegates to `tools/run-owned-route-build.mjs`. It validates before writing, runs the ordered list in `tools/route-writer-manifest.mjs`, checks that post-processor inputs exist, and validates again after generation. `npm run routes:dry-run` prints the exact order without writing. `npm run routes:validate` performs ownership-only validation.

The recovered SPA has no server-side route renderer. Consequently, `generate-spa-routes.mjs` must not replace an existing owned route with the homepage entry document: doing so couples route output to unrelated homepage edits and can discard approved route-specific raw HTML before finalizers run. Existing SPA-owned route output is preserved as the static input to registered route finalizers; the generic entry document is a missing-route fallback only.

The repository validator also enforces the declared runtime shape: React routes require a module bootstrap and may not substitute registered/static navigation or chat assets; static routes may not contain a module bootstrap; and explicitly registered static navigation/chat dependencies must appear in the route markup. Two pre-existing exceptions are declared in executable metadata rather than hidden in validator heuristics: Edmonton → Montreal currently has its React bootstrap stripped and uses static navigation/chat, while Ottawa → Victoria retains a module tag under its dedicated static owner. Those unrelated classifications remain review items outside Step 37A; new contradictions fail validation by default.
